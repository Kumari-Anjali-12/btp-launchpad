# Production Deployment Runbook: SAP BTP Cloud Foundry
## Multi-Target Application Deployment for Employee Leave Management System

This runbook provides complete operational instructions for deploying the standalone Employee Leave Management System to SAP BTP Cloud Foundry with SAP HANA Cloud and XSUAA.

---

## 1. Prerequisites & Cloud Entitlements

Ensure your target SAP BTP Subaccount has the following entitlements assigned in the **SAP BTP Cockpit** (**Entitlements > Configure Entitlements**):

| Service | Plan | Quota Required | Purpose |
| :--- | :--- | :--- | :--- |
| **SAP HANA Cloud** | `hana` / `hdi-shared` | 1 instance | Columnar relational database container for persistent tables. |
| **Authorization & Trust (XSUAA)** | `application` | 1 instance | OAuth 2.0 authentication and role collection management. |
| **Cloud Foundry Runtime** | `standard` | 1024 MB | Application runtime memory for server and approuter containers. |

---

## 2. Tooling Requirements

Ensure the deployment machine or CI/CD runner has:
1. **Cloud Foundry CLI (`cf`):** Version 7 or 8.
2. **Cloud MTA Build Tool (`mbt`):** Installable via `npm install -g mbt` or binary download.
3. **Multiapps CF Plugin:** Install via:
   ```powershell
   cf install-plugin multiapps -f
   ```

---

## 3. Step-by-Step Deployment Procedure

### Step 1: Navigate to the Standalone CAP Project
```powershell
cd G:\BTP-Launchpad\projects\employee-leave-management
```

### Step 2: Validate Local Tests Before Packaging
```powershell
npm test
```
*Do not proceed if any test fails.*

### Step 3: Build the Multi-Target Application Archive (MTAR)
```powershell
npx mbt build -t gen/mta
```
*What happens:*
- Compiles CDS models to `gen/srv` and `gen/db`.
- Packages all modules into `gen/mta/employee-leave-management_1.0.0.mtar`.

### Step 4: Login to Cloud Foundry & Target Space
```powershell
cf login -a https://api.cf.eu10.hana.ondemand.com -o <YOUR_ORG> -s dev
```

### Step 5: Execute Deployment via Cloud Foundry
```powershell
cf deploy gen/mta/employee-leave-management_1.0.0.mtar
```

### What the Multiapps Deployer Orchestrates:
1. Creates service instance `employee-leave-db` (HANA HDI container).
2. Creates service instance `employee-leave-auth` using configuration from `xs-security.json`.
3. Runs database deployer task (`@sap/hdi-deploy`) to initialize HANA tables and sequences.
4. Starts the Node.js CAP backend (`employee-leave-srv`).
5. Starts the Application Router reverse proxy (`employee-leave-approuter`).

---

## 4. Post-Deployment Role Configuration in SAP BTP Cockpit

1. Open the **SAP BTP Cockpit** and navigate to your Subaccount.
2. Under **Security**, click **Users**.
3. Select your user account (or team member accounts).
4. Under **Role Collections**, click **Assign Role Collection**.
5. Assign the appropriate role collections generated by `xs-security.json`:
   - `LeaveEmployeeRoleCollection`: Allows submitting leave requests and viewing personal balances.
   - `LeaveManagerRoleCollection`: Allows manager approvals on team leave requests.
   - `LeaveAdminRoleCollection`: Allows HR administrators to modify policies and run accruals.

---

## 5. Smoke Testing the Live Deployed Application

1. Retrieve the public URL from the deployment output or run:
   ```powershell
   cf app employee-leave-approuter
   ```
2. Open the URL in an incognito browser window.
3. Authenticate with your SAP ID Service credentials.
4. Verify that:
   - The Fiori launchpad loads cleanly.
   - Leave requests table populates data.
   - Role permissions correctly enforce or restrict manager actions.
